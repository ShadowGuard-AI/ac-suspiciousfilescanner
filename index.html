Five Signs in One File

ac-SuspiciousFileScanner takes one file at a time. Its five checks each answer a different question about the file:

Entropy, and whether it runs high.

A search for the embedded ZIP signature bytes.

Printable strings, and whether any run unusually long.

A file type read from magic bytes.

Matches against YARA rules.

depth: surface

The Call

Install first:

git clone https://github.com/ShadowGuard-AI/ac-suspiciousfilescanner
cd ac-suspiciousfilescanner
pip install -r requirements.txt

Then the call itself, with three optional flags shown as depth settings a caller can move:

python3 main.py FILE_PATH [--yara-rules-dir DIR] [--entropy-threshold NUMBER] [--min-string-length NUMBER]

-h shows help.

depth: the call

Resting Depths

FILE_PATH is the file to scan.

--yara-rules-dir names the directory holding YARA rules and rests at yara_rules.

--entropy-threshold rests at 6.0 and decides what counts as high entropy.

--min-string-length rests at 50 and decides what counts as a long string.

depth: settings

What Testing Established

A missing input file exits 1.

A YARA rules directory that does not exist draws a warning, YARA scanning is skipped, and the remaining checks still run.

Printed long strings stop at 100 characters.

A Signature Is Not an Archive

The ZIP check searches for the PK\x03\x04 signature bytes rather than parsing an archive, so a hit reports a signature found, not a proven embedded archive.

depth: verified

The Honest Bottom

A live run was not possible in the environment where this README was verified, because the filetype and yara packages are not installed there and installs were not permitted in that wave.

The parameter list comes from the argument parser in main.py, and the file compiles cleanly, so a visitor knows which claims were exercised and which were read from the code.
